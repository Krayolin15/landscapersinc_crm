Putting the app online

The app is a set of static files, so any static host works. Do SETUP-SUPABASE.html first, and set mode: 'supabase' with your Supabase address and anon key in js__settings.js.

Before you upload

  • Never upload data/seed/, data/vault/, data-tools/ or the zip. Once live, the company data lives in Supabase behind logins. A data pack on a web host can be downloaded by anyone who guesses the address. The .gitignore already keeps these folders out of git.
  • Never drag the whole landscapers-hq folder onto a host or into GitHub's upload page. Make a separate upload folder with only the files listed below.
  • The host must serve HTTPS. Phones need it for installing the app, offline use, the camera, GPS check-in and notifications. All three hosts below provide it free.
  • Keep the hidden file .nojekyll at the top of the upload folder: GitHub Pages would otherwise drop files whose names start with _, such as js__apps___biz.js.

Upload these: index.html, sw.js, manifest.webmanifest, .nojekyll, and the assets/, css/, js/ and vendor/ folders. The docs/, supabase/, tools/ and tests/ folders and README.html are harmless but not needed by the browser.

Security headers (Netlify and Cloudflare Pages)

These hosts add extra security headers when the upload folder contains a plain-text file named _headers (no extension). It is not kept in the project, so create it in the upload folder just before you upload, with exactly these lines:

/*
  X-Content-Type-Options: nosniff
  Referrer-Policy: strict-origin-when-cross-origin
  X-Frame-Options: DENY
  X-Robots-Tag: noindex, nofollow

/sw.js
  Cache-Control: no-cache

The last two lines make sure every phone always gets the newest version of the offline cache. GitHub Pages ignores this file.

Option A: Netlify (simplest)

  1. https://app.netlify.com → Add new site → Deploy manually.
  2. Drag the prepared upload folder onto the page.
  3. Domain management: add your own domain (for example hq.landscapersinc.co.za) or keep the free …netlify.app address.

To update, drag the new folder onto Deploys.

Option B: Cloudflare Pages

Workers & Pages → Create → Pages → Upload assets, then upload the folder. Custom domains are under Custom domains.

Option C: GitHub Pages

  1. Put the code on GitHub with git, as in the README (never with the website's upload page). Choose a private repository; .gitignore keeps data/seed/, data/vault/, data-tools/ and node_modules/ out.
  2. Settings → Pages → Deploy from a branch → main / root.

GitHub Pages has no extra security headers; everything else works. Pages from a private repository needs a paid GitHub plan.

After the first deploy

  1. In Supabase, Authentication → URL Configuration: set Site URL to the live address and add it to Redirect URLs.
  2. Open the address, sign in, and check Admin → System.

Installing on phones and PCs

DeviceHow
Android (Chrome)Open the address → menu ⋮ → Install app (or accept the install banner)
iPhone / iPad (Safari)Open the address → Share → Add to Home Screen
Windows / Mac (Chrome or Edge)The install icon in the address bar

The installed app opens full screen, starts instantly, and keeps working with poor signal. Changes made offline are sent when the connection returns. (Installing needs the hosted address; a copy opened by double-clicking index.html cannot be installed.)

Releasing an update

  1. Upload the new files the same way.
  2. Phones fetch the new code on their next load, because app code is loaded network-first. When a release changes the offline shell list, VERSION in sw.js is raised, which clears old caches.
  3. If the release notes mention database changes, run steps 01–05 again from Admin → Go live (safe to re-run, keeps all data).

A custom domain for email

For invoices and reminders to come from your own address, verify the domain in Resend (add the DNS records it shows), then set MAIL_FROM (SETUP-SUPABASE.html).
