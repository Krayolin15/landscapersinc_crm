Landscapers Inc. HQ

The company's own workspace and CRM: mail, calendar, drive, docs, sheets, slides, forms, chat and meetings, plus clients, leads, quotes, invoices, payments, live dispatch, fleet, people, health and safety, finance, KPIs, an AI assistant (Sage) and a 24/7 autonomous agent. Every file is plain HTML, CSS or JavaScript, and it runs by opening index.html. Supabase provides the shared database, logins, file storage and the always-on agent once you go live.

Built for Landscapers Inc., Mount Edgecombe, Durban. Times are South African (SAST), money is in rand, and the calendar includes the South African public holidays.

Open it on one computer

Nothing to install. Everything runs in the browser, and nothing leaves that computer.

  1. Unzip the zip to a short place, for example C:\LSI (right-click the zip → Extract All…). Windows cannot open documents in very deep folders, so the app warns you if the folder sits too deep. Do not open index.html from inside the zip.
  2. Open the landscapers-hq folder and double-click index.html. Google Chrome or Microsoft Edge work best.
  3. The first start loads the company records, which takes a few seconds.
  4. Tap your name and sign in with the password you used in the old CRM. You will be asked to choose your own password.

Every original document (invoices, certificates, medicals, policies, site photos, the Carron Glen proposal…) opens straight from its record or from Drive, in the browser's own viewer. A few features need to read a document's contents inside the app: importing an original spreadsheet into Sheets, putting an original photo into a slide PDF, attaching an original to a message. For those, go to Drive → Load original documents once and choose the data/vault folder. The browser then keeps a checked copy of each document.

The records live in that browser's storage on that computer. Clearing the browser's site data erases them, so download a copy now and then from Admin → Backup.

Forgot your password? Nobody can read a password back (they are stored scrambled), but you can set a new one: double-click reset-password.html in the landscapers-hq folder, choose your name and type a new password, then sign in with it. Use the same browser as for the app. It works only on that computer, and every reset is written to the audit log and shown in everyone's notifications. An administrator can also reset anyone's password under Admin → Users.

Optional: run it as a small local web server

This gives the same app, plus installing it on the computer and opening it offline; documents then need no extra step. It needs Node.js 18 or newer. In the landscapers-hq folder run:

node tools/serve.js 8080

Then open http://localhost:8080.

Go live (Supabase)

This gives everyone their own login, one shared database protected by Row Level Security, file storage, realtime updates, email, and the agent running at 05:00 and 05:30 every day even when nobody is signed in.

  1. docs/SETUP-SUPABASE.html: create the project, then in the app open Admin → Go live, which hands you the SQL for every step, ready to copy or download. Deploy the server code with node tools/deploy-functions.js and upload the original documents with node tools/upload-vault.js.
  2. Put the Supabase address and the public (anon) key in js/settings.js. It is the only file you edit, and the app reads it straight away, opened by double-click or hosted.
  3. docs/DEPLOY.html: put the app online, without the private folders, and install it on phones.

Put the code on GitHub

The .gitignore in the folder keeps data/seed/, data/vault/, data-tools/ and any PRIVATE zip out of git, so only the code goes up.

Never drag the folder into GitHub's website upload page. That ignores .gitignore and would publish the company data. Use git from the folder, as below.

  1. On GitHub create a new repository, for example landscapers-hq. Choose Private (recommended for a company system). Do not add a README or .gitignore there.

  2. In the landscapers-hq folder run, one at a time (replace <you> with your GitHub user name):

    git init -b main
    git add .
    git status

    Check the list: it must not show data/seed/, data/vault/, data-tools/ or any PRIVATE zip. Then:

    git commit -m "Landscapers Inc. HQ"
    git remote add origin https://github.com/<you>/landscapers-hq.git
    git push -u origin main

npm run check (below) also stops with an error if company data, a document or a service_role key is ever committed. Publishing the app itself is in docs/DEPLOY.html.

Everything is HTML, CSS and JavaScript

  • The app: HTML, CSS and JavaScript modules in js/. js/app.bundle.js is the same code as one file, which is what runs when index.html is double-clicked (browsers refuse to load modules from a folder); js/boot.js picks the right one.
  • The company records: JavaScript files in data/seed/ (browsers will not read .json files from a folder either).
  • The database SQL: written by JavaScript in js/sql/, so there are no .sql files to keep in step. Admin → Go live shows it; npm run sql writes it to files for psql.
  • The server code (Edge Functions in supabase/functions/), the tools and the tests: JavaScript.
  • These guides: HTML pages.
  • JSON only where npm and phones require it: package.json, package-lock.json and manifest.webmanifest.

For developers

The app needs no build step to use or host. The tools are optional and need only Node.js.

npm install
npm test
npm run test:sql
npm run check
npm run build
npm run test:browser
  • npm test runs the unit tests (521 in 21 files): formulas, money, dates, forms, PDF layout (no overlapping text on any invoice, quote or statement), Sage, agent rules, the go-live SQL, the zip tools, the links in these guides and more.
  • npm run test:sql runs all the go-live SQL against a real Postgres (PGlite), loads the company records if they are in data/seed/, links logins and checks Row Level Security for eight roles (51 checks with the records, 50 without).
  • npm run check parses every module and checks its imports, that js/app.bundle.js is up to date, that every file is HTML, CSS or JavaScript, and, in a git repository, that no company data or key is committed.
  • npm run build rebuilds js/app.bundle.js, the double-click version. Run it after changing anything in js/ (not needed for js/settings.js, which is read separately).
  • npm run test:browser opens the app in headless Chrome or Edge, both double-clicked and served: the records load, every app opens, documents open, an invoice PDF downloads with its logo, and Load original documents works.
  • npm run sql writes the go-live SQL to build/sql/ for psql (step 06 holds private data; build/ is git-ignored).
  • npm run seed -- --knowledge <dir> rebuilds the company records from the extracted knowledge files (needs data-tools/).
  • node tools/build-vault.js rebuilds data/vault/ from the original company zips, and node tools/upload-vault.js --dry-run checks every document against its record before an upload to Supabase Storage.
