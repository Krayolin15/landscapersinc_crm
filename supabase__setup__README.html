Landscapers Inc. HQ — Live Database

This project contains a real Supabase/Postgres deployment package. The browser code already uses Supabase Auth, Postgres, Row Level Security, Realtime and a local offline cache when Supabase is configured.

1. Create the live database

Create a Supabase project. In the Supabase SQL Editor run ../migrations/20261006_lsi_hq_core.sql, then run ../seed.sql.

The core migration creates the application tables, indexes, Row Level Security policies, attribution/audit triggers, Storage buckets and Realtime publication. The seed loads the company data pack shipped in this private ZIP.

Private data: supabase__seed.sql contains company information. Do not commit or publish it. The project's .gitignore excludes it.

2. Connect the app

Edit js__settings.js:

globalThis.LSI_SETTINGS = {
  mode: 'supabase',
  SUPABASE_URL: 'https://YOUR_PROJECT_REF.supabase.co',
  SUPABASE_ANON_KEY: 'YOUR_PUBLIC_ANON_KEY'
};

Use only the public anon/publishable key. Never put the Supabase service_role key in the browser.

3. Staff logins

Create each staff user under Supabase Authentication → Users. Then fill the real email addresses into 08_link_accounts.template.sql and run it. This preserves the imported profile history and links it to the new Supabase Auth user.

4. 24/7 automation

After deploying the existing Edge Functions and setting their secrets, run 07_cron.sql with your actual project ref. The app already contains the 24/7 agent functions and the Admin → Go live workflow.

5. Regenerate

When schema or seed data changes, run npm run db:prepare. The source of truth remains js/schema/ and js/sql/.
